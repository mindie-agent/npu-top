# Ascend 950 (A5) 探测与解析说明

**中文** · [English](./a5-probing.md) · [返回文档中心](./README.md)

新一代 **Ascend 950（简称 A5，如 Ascend950DT）** 的 `npu-smi info` 表格排版跟早期的 910B（单 Die）和 A3 / 910C（双 Die）明显不同。`npu-top` 内置解析器专门针对 A5 的四列布局做了原生适配，并把采自 4 台真实 Ascend950DT 服务器的输出样本（固件版本 `26.2.0.b007`）保存在了 `tests/fixtures/a5-*.txt` 中用于自动化回归测试。

---

## A5 的 `npu-smi info` 输出有什么特点？`npu-top` 怎么解析？

1. **四列双行设备表**：
   - **第一行（主行）**：给出单个设备 ID、芯片型号（如 `Ascend950DT`）、健康状态（`Health`）、功耗（W）和温度（℃）。
   - **第二行（续行）**：给出总线地址（`Bus-Id`，在部分环境可能显示为 `NA`）、NPU 利用率（`%`）、内存以及 HBM 显存占用（例如单卡 `98304 MiB`）。
2. **进程表不再有 Chip ID 列**：
   A5 的占用进程行直接列出设备 ID、宿主机 PID（以及可选的容器内 PID）和显存占用，`npu-top` 直接按真实设备 ID 映射，不再人为拼接虚拟的 Chip ID。
3. **不乱调不支持的全局 `usages` 命令**：
   在 A5 上运行不带卡号的 `npu-smi info -t usages` 会报错要求传卡 ID；而 A5 的主表本身就已经带齐了利用率和显存数据，所以解析器直接采用主表指标，不会用失败的全局 `usages` 输出去冲掉正常数据（老款 910B / A3 则继续走原有解析流程）。
4. **遇到残缺输出直接报错，绝不伪造“0 张卡在线”**：
   如果远端命令返回了无法识别的空文本、或者 A5 指标行被截断，采集器会直接把这次探测标记为失败，**绝不会假装“探测成功，这台机器有 0 张卡”**。同时，机器连通性和单卡健康度是分开展示的——一台在线的服务器里可以正常显示某张卡处于 `Warning` 告警状态。

---

## 如何在本地跑 A5 解析回归测试？

不需要连接真实的 A5 物理机，直接在本地运行测试套件即可验证所有真实样本（覆盖 8 卡 98,304 MiB HBM、`Warning` 状态、功耗/温度、进程显存占用、非零利用率以及异常截断报错）：

```bash
python3 -m pytest -q tests
```
