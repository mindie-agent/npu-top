# Ascend 950 (A5) NPU 探测与解析

**中文** · [English](./a5-probing.md) · [返回文档中心](./README.md)

`npu-top` 使用内置解析器处理单 ID 四列布局的 Ascend 950（A5）`npu-smi info` 表格输出。来自四台 Ascend950DT 宿主机的 `26.2.0.b007` 实采输出已作为回归测试固件保存在 `tests/fixtures/a5-*.txt`。

## 解析规则

- **设备主行与续行**：首行提供设备 ID、名称、健康状态（Health）、功耗与温度；续行提供总线地址（Bus ID，可能为 `NA`）、NPU 利用率、内存与 HBM 占用。
- **进程行**：包含设备 ID 与宿主机 PID（以及可选的容器内 PID），不再人为合成虚拟 Chip ID。
- **全局与单卡 Usages**：A5 的 `npu-smi info -t usages` 要求显式传入卡 ID；由于总览表已直接提供完整利用率指标，解析器不会使用不支持的全局 `usages` 响应覆盖 A5 指标。旧版单 Die / 双 Die 布局继续走既有解析路径。
- **严格错误暴露**：无法识别的空输出或不完整的 A5 指标行会直接判定该次采集失败，绝不伪造“0 设备在线”的假成功快照。宿主机连通性与单卡健康度相互独立：在线宿主机可以包含处于 `Warning` 状态的设备。

## 验证方式

```bash
python -m pytest -q tests
```

回归测试固件覆盖每台主机 8 张设备、单卡 98,304 MiB HBM、`Warning` 健康状态、功耗/温度、宿主机占用进程（341 MiB 显存分配）、非零利用率以及畸形输出报错，无需物理 NPU 即可在本地完整运行。
